# 情境维度进预测:必须样本量门槛保护, 宁可不说不可瞎猜

场景
用户可选填的情境标签(家/工作/社交/压力)、心情(mood)等维度, 数据稀疏且非必填。想把它纳入预测/洞察做"被理解感", 但直接算会导致大量不靠谱结论。

做法
1. 主导情境归因: 统计指定时段内的情境分布, 取次数最多的, 但要求 checkin_count >= 3 才输出("20:00-22:00 这段对你来说最难, 多在「社交」场景")
2. 条件模式: 按情境算"日均值"(total/不同天数), 取最高与最低对比, 要求两侧 days >= 2 且比值 >= 1.5 才输出("「压力」时平均每天6.2根, 是「家」的3.1倍")
3. 用"天数"而非"次数"做分母: 同一天记10次会污染平均值, 必须按 distinct date 聚合
4. 不满足门槛时静默省略该字段, 前端按字段有无决定是否渲染, 不留空占位
5. 仓储层用 context_tag != '' 过滤掉空值, 避免空标签成为"最高频情境"

原因
- 稀疏数据上的统计极易得出偶然结论, 用户一旦发现"瞎说"就不再信任整个预测模块
- 预测的准确性 × 可信度才是价值; 一个不靠谱的情境归因会连累整个预测的可信度
- "宁可不说"符合惜字如金: 没有把握时少说一句, 比多说一句错的更好
- 按天数聚合避免"某天暴记"造成的均值失真

反例
- 只有1次"压力"记录就说"压力时你抽得最多" → 偶然
- 用checkin次数当分母 → 同一天多记几次就把均值拉偏
- 没有数据也显示"情境: 未知"占位 → 噪音
- 把空context_tag也算作一类 → 空值成了主导情境

验证
challengePlanet: 集成测试造7天数据(social3天/home2天/work2天)验证主导情境=社交且条件模式生成; 同时验证仅2个活跃时段(样本不足)时风险窗口被正确抑制
