# 预测要前瞻(接下来何时)而非只回溯外推(今日终值)

场景
习惯/健康/风控类产品做"预测"时, 容易停留在"回溯外推": 用今天已发生的量按时间比例推算今日终值("预计今天11根")。这仍是描述过去, 用户看完不知道该干嘛。

做法
1. 前瞻窗口: 从小时分布里只取"当前时刻之后"(h > now)的时段, 过滤掉权重过低的噪声(hour权重 >= 0.06), 取权重峰值并向两侧扩展到权重 >= 峰值*0.6 的连续区间 → 得到"接下来最危险/最佳时段"
2. 方向语义分叉: decrease 方向=风险窗口("最容易失守"); increase 方向=机会窗口("状态最好")
3. 文案走被理解感: "20:00-22:00 这段对你来说最难, 提前安排点别的"(共情) 而非 "你20-22点破戒率最高"(评判)
4. 无记录也要给: 用户"今天还没记录"时恰恰最需要前瞻提醒, 不能因为 enabled=False 就吞掉窗口
5. 样本不足不出: 置信度 < 0.45(活跃时段<4)时返回空窗口, 宁可不给也不瞎猜

原因
- 前瞻才可行动: 用户能据此"提前安排点别的"; 回溯外推只能让人事后懊悔
- 被理解感是留存锚点: 评判式文案让用户感到"被监视", 共情式让用户感到"被理解"(brainstorm文档红帽结论)
- 竞品多停留在静态模式识别("你周三容易破戒"), 动态前瞻窗口(随当前时刻变化)是体验差异
- 纯函数零LLM, 数值判断不用大模型(项目铁律)

反例
- 只在"今日已有记录"时给窗口 → 最该提醒的空白日反而没提醒
- 用全量分布(含已过时段)找峰值 → 下午3点时还在提醒你"早上8点危险"
- 样本只有1天也强行给"高置信度窗口" → 打脸
- 前瞻文案写成评判("你又要在20点破戒了") → 用户产生被监视感而抗拒

验证
challengePlanet: 单测7例(晚间高危/今日未记录仍给/已过时段无窗口/样本不足不给/increase最佳时段) + e2e 15例全绿
