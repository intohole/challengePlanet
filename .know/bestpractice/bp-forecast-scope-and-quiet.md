# 预测先定边界: 只对"有节奏的行为"预测, 且深夜/清晨/低样本下静默

场景
已有一套"按今日进度外推今日终值"的节奏预测, 被用户抓到两处硬伤: 10:00 已记4根却预计18根、触顶13:09(实际全天约11-13根); 凌晨抽烟时段直接给出无意义断言。

两处根因(实测复现)
1. 模型口径与计数口径不一致: 记录按自然日累计(0点起算), 但作息画像只取 6-24 时, 凌晨(0-5)的烟既计入今日总量、又不计入今日已流逝节奏 → 分母偏小 → 10点4根被外推成 18 根。修正=画像覆盖 0-24 时, 同一数据下预测回到 12-13 根。
2. 无边界断言: 0-6 点、今日记录不足2笔、一天刚开头时, 任何"预计/触顶/预计达标时刻"都是瞎猜; 触顶时刻还只在"预计会超"时才该出现(在计划内却报触顶会自相矛盾)。

做法
1. 场景门禁(forecast_scope.supports_forecast): 只有 counter 与"时长类单位"的 timer 做预测; 按时点记录的 timer(早起)、binary/text/word/recite/diet/step/时段拆分(time_slot)一律不预测, 前端回落到"守住X以内即为今日达标/还差X"
2. 静默门槛(forecast_math.display_ready): hour < 6 或 (今日记录 < 2 且时间进度 < 0.25) 时, projected=0/触顶留空/依据留空, 但仍保留"已记/还可 X"与前瞻窗口(窗口是前瞻信息, 静默不该吞掉)
3. 预测分母(day_progress) = max(画像已流逝占比, 时间占比, 0.15): 第二个地板吞掉"早上零记录"的极端外推, 0.15 地板保证刚开盘时不放大到几十倍
4. 预测口径与计数口径必须同源: 画像时段 = 计数时段(自然日 0-24); 跨零点作息用户的高危窗口允许跨夜(20点后窗口可给出 01:00-02:00)
5. 提示阶梯: 逼近(1)→已到上限(1, 不再弹toast)→已超上限(2, 升级提醒)

验证
challengePlanet: e2e_nudge_service 64例(含凌晨静默/样本门槛/凌晨纳入画像/跨夜窗口/单点窗口)、test_forecast_service 门禁23例、e2e_forecast_dashboard 45例、线上真实数据脚本(challenge 60: 10点4根→预计9.6根, 无触顶断言, 窗口20:00)

反例
- 记录按自然日、画像按"白天"→ 凌晨记录左脚踩右脚, 预测翻倍
- 深夜给"预计X根/触顶HH:MM" → 用户一眼认定预测不可信
- 对所有场景一律预测 → 打卡开关/文字记录/背单词页面上出现无意义"预计X达标"
- 静默时连"还可X"和前瞻窗口一起吞掉 → 用户失去当日唯一可行动信息
