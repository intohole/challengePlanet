# 预警类预测:给单个数字+定性把握, 不要区间(附认知纠正)

场景
任何面向C端用户的"预警/提醒"类预测(习惯预测/健康预警/风险提示)。曾误以为要给出区间和精度才显专业可信。

认知纠正(重要)
初版我给预测加了区间 "预计 11±2.2 根" 和 1 位小数, 以为"给区间=诚实=可信"。用户一句话点破:
  "还是用预计一个数字就可以 你是预警 不是为了准确"
这是根本性的定位错误: 我把一个"预警"做成了"数据报表"。

做法(修正后)
1. 只给一个预计数字, 且取整: "预计 11 根"。预警是"一眼可读+立刻行动", 不是精度展示
2. 保留一句依据: "按你最近两周的同时段节奏"(用户知道为什么)
3. 保留定性把握: "中把握"(告诉用户这条预警多可信 —— 这才是预警该有的不确定性表达)
4. 用"左右/大约"这类人话表达不确定, 绝不用"±"(统计/工程记法, 不是人话)
5. 区间(projected_low/high)只在真正做数据分析的产品里才需要; 预警场景它是纯噪音, 应删除而非保留
6. 删除连带复杂度: interval_of 区间计算、apply_bias 的区间平移 —— 为一个不需要的功能维护三处代码

原因
- 预警的价值 = 可读性 × 可行动性, 不是统计严谨性。多一个数字就多一分认知负担
- "±" 是专业圈记法; 大众用户读不懂, 反而觉得"这什么玩意儿"
- 小数值是假精确: "预计 11.2 根烟"毫无意义, 整数才诚实
- 不确定性用定性词("中把握")比定量区间更适合预警: 用户要的是"该不该信", 不是"置信区间"
- 删掉不需要的功能比保留"可能有用的字段"更符合"避免过度设计"

反例(我踩过的)
- 给预警加 ± 区间 → 变成报表, 用户读不动
- 用 .1f 格式化 → 出现 "9.0 根""4.0 根" 尾零, 或 JS 浮点 13.2-11=2.200000000000001 直接拼进文案
- 保留 projected_low/high 字段"以防将来用" → 死字段 + 三处连带复杂度
- 同一信息重复展示(窗口文案含「社交」场景, 元信息又挂一个"社交"chip) → 违反惜字如金

验证
challengePlanet: 113例全绿, 含专门守坑断言"预计为单个数字(无左右)""无多余小数""无±工程记法""无浮点垃圾小数"
