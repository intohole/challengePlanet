# 预测/洞察文案要回答用户的问题, 不是翻译算法输出

场景
任何把算法/统计数据转成用户文案的场景(预测、洞察、报告、预警)。文案写完自己读一遍: 用户看完能得出一个可行动的结论吗?

核心教训
"看不懂"往往不是措辞问题, 而是**回答了错误的问题**。

我的踩坑(阶梯预测):
原文案: "按现在的水平, 结束时约 18根, 离目标还差 17根"
用户: "这句话我看不懂"

拆解为什么错:
1. 它把"现在的量"直接外推成"结束时的量" —— 完全忽略了阶梯计划本身
   (用户设的是 20根→目标1根→隔3天减1支, 系统每天都在自动下调上限)
   说"结束时约18根"等于说"你的习惯永远不会降", 那阶梯计划是干嘛的? 自相矛盾
2. "离目标还差17根" 拿当前量直接比最终目标(1根) —— 只给恐慌, 不给信息
3. 它回答的是"照这势头能到目标吗"(一个算法视角的问题)
   而用户想知道的是"我有没有跟上计划"(一个用户视角的问题)

修正后: "最近7天平均 20根, 比阶梯计划高 3根" / "最近7天平均 6根, 在阶梯计划内"
—— 直接回答"跟上没", 且给了可行动的差距

做法
1. 写文案前先问: 用户此刻真正想知道的是什么? (不是"我的算法输出了什么")
2. 指标要选"用户能对照的参照系":
   - 错: 实际 vs 最终目标(跨度太大, 无行动性)
   - 对: 实际 vs 计划上限(当下就能对照, 有行动性)
3. 检查自相矛盾: 文案的隐含假设是否与产品机制冲突?
   (说"永远不降" vs 产品是"自动递减阶梯")
4. 避免"只给恐慌": 差距数字必须配可行动的方向
5. 自检法: 把文案读一遍, 问"用户看完知道下一步做什么吗?"

反例
- 把算法输出直接翻译成人话 → 措辞可能通顺, 但答非所问
- 用跨度极大的参照系(当前值 vs 最终目标) → 数字吓人但无用
- 文案隐含假设与产品机制冲突 → 用户觉得"这app不懂我的计划"
- 只报差距不给方向 → 焦虑但不行动

验证
challengePlanet: 116例全绿, 新增断言"比阶梯计划高""在阶梯计划内""不再出现'离目标还差'"
