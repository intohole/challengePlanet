# 数据卡片打磨:消除重复渲染+单一签名可视化+三层信息梯度

场景
预测/进度类数据卡片越加越多信息, 最后变成一堵小字墙; 且容易出现同一指标被多处渲染(重复进度条)。

做法
1. 先做重复渲染审计: 逐个函数看谁画了什么。challengePlanet 曾出现 _ladderBlock 与 cp-task-progress 各画一条进度条, 又各自显示"已记/余量" → 双条+重复数字。修法: 让一个函数独占该视觉, 另一个跳过(goal_rule!=='ladder' 才画通用条)
2. 立单一签名可视化: 选一个能承载"核心判断"的图形做主角。challengePlanet 用"节奏轨"——同一条轨上画 已记填充 + 上限刻度线 + 预计终点标记; 预计标记落在上限线右侧 = 一眼看出"会超"。这比一排数字直观得多
3. 三层信息梯度(全部≥12px, 靠大小/颜色/透明度分层, 不靠缩小字号):
   - 关键指标: 16px 粗体 tabular-nums
   - 可行动提示: 12px 主色(如风险窗口文案)
   - 元信息: 12px muted + 小chip(依据/校准/情境)
   - 洞察面板: 12px + 顶部虚线分隔
4. 状态色只上标记不上卡片: 稳(emerald)/将超(amber)/已超(red) 只用于轨道填充与预计标记, 卡片底保持中性
5. 可访问性: 图形加 role="img"+aria-label 描述数值; 校验 375 宽无横向溢出、标记不出轨

原因
- 重复渲染是数据卡片的隐性缺陷, 会让用户困惑且显得粗糙
- 一个签名可视化能把"需要读3个数字才能得出的判断"变成"扫一眼就懂"
- 字号是移动端可读性底线, 不能用缩小字号来塞信息; 梯度靠weight/color/opacity
- 卡片底染色会与状态色冲突且显得廉价, 颜色应集中在数据标记

反例
- 同一指标画两条进度条 → 用户以为有两个指标
- 全部信息同一字号 → 没有层级, 读起来累
- 用 11px 以下字号塞信息 → 移动端看不清
- 卡片底按状态染红/绿 → 廉价且与标记色打架
- 只靠颜色区分状态 → 色盲用户不可辨(需同时有刻度/标记位置差异)

验证
challengePlanet: e2e 27例, 含"无重复进度条"、"节奏轨存在/有预计标记/有上限刻度/aria-label"、"375宽无横向溢出"、"预计标记在轨内"、"已超态填充为红rgb(239,68,68)"
