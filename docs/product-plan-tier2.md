## 一、JTBD 分析：用户雇佣跬步完成什么"工作"

### 1.1 三层任务识别

用户不是"要一个打卡 App"，而是雇佣跬步完成三层任务：

| 层级 | 用户雇佣跬步完成的任务 | 当前是否满足 |
|------|----------------------|-------------|
| **功能任务** | 在行为发生的当下（不是一天结束时），让习惯的进展可见、可调、可纠偏 | ❌ 现状一天只能打卡一次，无法记录"8点抽了1根、9点又抽了1根" |
| **情感任务** | 把"我又失败了"的自责，转化为"我在这个时段容易破戒，可以调整"的掌控感 | ❌ 现状 binary 打卡：要么成功要么失败，没有中间态，自责感强 |
| **社会任务** | 让朋友/小队看到我的真实进展（不是美化后的"今日已打卡"），获得精准鼓励 | ⚠️ 现状有分享和小队，但只能分享"打卡了"，无法分享"今天比昨天少抽了2根" |

### 1.2 二级打卡解决的真正痛点（不是"记录更多"）

**表面需求**："每天打卡，但比如抽烟，每个小时抽烟数量也要记录"

**追问3层 Why**：

| 追问 | 用户的真实回答（推演） |
|------|---------------------|
| 为什么每小时都要记？ | "因为一天记一次太粗了，我根本不知道自己什么时候抽得多" |
| 为什么不知道什么时候抽得多是个问题？ | "因为我设了'每天不超过5根'的目标，但每天到晚上才发现超了，来不及调整" |
| 为什么来不及调整是个痛点？ | **"因为习惯不是在'一天'的粒度上发生的，是在'每个时刻'上发生的。如果我不能在行为发生的当下看到进展，我就无法在当天内纠偏——我只能等明天重新开始。"** |

**核心洞察**：二级打卡解决的不是"记录更多数据"，而是 **"实时纠偏能力"**。

> 类比：你开车时，仪表盘每秒更新速度，而不是每天告诉你"今天平均超速了20%"。没有实时反馈，你根本无法在当下调整脚下的油门。

**二级打卡 = 把习惯的反馈周期从"天"缩短到"时段"**，让用户在当天内就能：
1. 看到当前累计值 vs 目标值
2. 发现"这个时段又破戒了"
3. 在下一个时段做出不同选择

### 1.3 目标拆解解决的认知负担

**表面需求**："目标是不断拆解的，比如25分钟打卡就一件事情"

**追问3层 Why**：

| 追问 | 真实回答 |
|------|---------|
| 为什么要把目标拆解？ | "30天戒烟太大了，我脑子无法把它变成'现在这一刻我该做什么'" |
| 为什么"现在该做什么"需要拆解才能明确？ | "因为大脑处理不了抽象的大目标，只能处理具体的、有时间和数量约束的小动作" |
| 为什么处理不了大目标是痛点？ | **"因为面对'30天戒烟'这种大目标，大脑的第一反应不是'行动'，而是'逃避'。目标越大越模糊，启动阻力越大，放弃概率越高。"** |

**核心洞察**：目标拆解解决的不是"把大目标变成小目标"（这只是手段），而是 **"降低行为启动阻力"**。

**理论支撑（Fogg Behavior Model B=MAT）**：
- 目标拆解 → 提升 **Ability**（把大任务变小任务，能力门槛降低）
- 时段目标（8-9点≤1根）→ 提供 **Trigger**（时间本身就是触发器）
- 软目标督促 → 微量 **Motivation**（有方向但不焦虑）

**目标拆解 = 把"30天戒烟"这个无法行动的抽象目标，转化为"8-9点这个时段不超过1根"这个可以立即行动的具体指令。**

### 1.4 用户价值公式

> 用户价值 = 新体验 - 旧体验 - 切换成本（俞军）

| 维度 | 旧体验（现状/竞品） | 新体验（跬步升级后） | 切换成本 |
|------|-------------------|-------------------|---------|
| 反馈粒度 | 日级（一天结束后才知道结果） | 时段级（当下就知道累计和差距） | 学习成本：用户需理解"多次打卡"概念 → 极低（点"+"即可） |
| 目标可行动性 | "每天≤5根"（仍需自己拆解何时抽） | "8-9点≤1根"（系统帮你拆到时段） | 学习成本：用户需理解目标层级 → 低（AI自动拆解，用户确认） |
| 失败感受 | 超了=今天失败（binary） | 超了软目标=提醒，不等于失败 | 心理切换：从"非黑即白"到"有弹性" → 中等（需UI引导） |
| 数据洞察 | 只有"连续天数"和"完成率" | "你在20-22点破戒率最高" | 0（纯增量价值） |

**结论**：新体验在反馈粒度和目标可行动性上有数量级提升，切换成本可控。用户价值为正且显著。

## 二、KANO 模型分析

### 2.1 功能分类矩阵

| # | 功能 | KANO 类型 | 判断依据 | 投入策略 |
|---|------|----------|---------|---------|
| F1 | 一天多次打卡 | **期望型** | 没有它，计数类习惯（抽烟/喝水/俯卧撑）用户会愤怒（"这都不支持？"）；有了它是理所应当，越多越灵活 | 持续优化，MVP 必做 |
| F2 | 时段记录（8-9点抽2根） | **兴奋型** | 没有它用户不生气（日累计也能用）；有了它"原来我可以记录时段！"——市场空白，形成口碑 | 适度投入，差异化卖点 |
| F3 | 软目标 vs 硬目标 | **期望型** | 没有软目标，每次超目标=失败，用户挫败感强、流失率高；有了软目标，满足程度线性提升 | 持续优化，MVP 必做 |
| F4 | 目标层级拆解（大→小→时段） | **兴奋型** | 没有它用户自己手动拆（能用但累）；有了它"AI帮我把戒烟拆到每个时段"——惊喜 | MVP 做简化版2级，Phase 2 做3级 |
| F5 | 25分钟停止拆解规则 | **兴奋型**（偏无差异边界） | 没有它用户不会主动要求；但过度拆解时会困惑"到底拆到多细？"——有了这个约束，减少决策负担 | MVP 做硬规则（成本极低），Phase 2 可AI化 |
| F6 | 24小时时段分布报表 | **兴奋型** | 没有它不影响基础使用；有了它"原来我总在20-22点破戒！"——颠覆性洞察，市场独家 | 差异化重点，MVP 必做 |
| F7 | 趋势对比报表 | **期望型** | 没有趋势图用户觉得"这App连个图表都没有？"；有了是理所应当 | MVP 必做（行业标配） |
| F8 | AI洞察分析 | **兴奋型** | 没有它用户自己看数据；有了它"AI发现你周一破戒率最高，建议周一晚上安排替代活动"——惊喜 | Phase 2 做（依赖足够数据积累） |

### 2.2 KANO 分布图

```
满意度 ↑
        │          F6(时段分布)     F8(AI洞察)
        │         F2(时段记录)  F4(目标拆解)
        │                    F5(25min规则)
        │
────────┼──────────────────────────→ 实现程度
        │  F1(多次打卡)  F3(软目标)
        │  F7(趋势报表)
        │
  不满  │
        │
```

### 2.3 投入策略总结

| 策略 | 功能 | 说明 |
|------|------|------|
| **做到及格线** | F1 一天多次、F7 趋势报表 | 期望型，不做用户会流失，做到可用即可 |
| **投入主要资源** | F2 时段记录、F3 软目标、F6 时段分布报表 | 兴奋型 + 期望型核心，差异化来源 |
| **轻量投入** | F4 目标拆解、F5 25分钟规则、F8 AI洞察 | 兴奋型，MVP 简化版，后续迭代深化 |
| **坚决不做** | — | 无反向型需求，所有功能均有正向价值 |

| F3 | 软目标机制 | 4000 | 2（降低流失） | 80%（Nudge理论支撑） | 2.0 | **3200** | 4 |

### 3.2 依赖关系处理

RICE 纯分数排序忽略了技术依赖。实际存在以下依赖链：

```
F1(一天多次) ──→ F2(时段记录) ──→ F6(24h报表)
                                        ↑
F4(目标拆解) ──→ 需要F1作为叶子节点打卡基础
                                        ↑
F3(软目标) ────→ 需要F2的时段数据才能做时段级软目标
```

**依赖约束**：F6 依赖 F2 依赖 F1；F3 的完整形态依赖 F2。

### 3.3 MVP Top 5 功能（考虑依赖后的最终排序）

| MVP 排名 | 功能 | RICE | 入选理由 |
|---------|------|------|---------|
| **1** | **一天多次打卡 + 时段记录**（合并实现） | 7500+3200 | 基础设施。没有它，F3/F4/F6 全部无法实现。合并后 Effort=2.5，综合 RICE 最高 |
| **2** | **软目标机制** | 3200 | 心理安全网。降低"超目标=失败"的挫败感，直接提升留存。可与#1并行开发 |
| **3** | **24小时时段分布报表** | 3600 | 差异化王牌。市场独家洞察，依赖#1的时段数据，是用户"啊哈时刻"来源 |
| **4** | **趋势对比报表** | 3333 | 行业标配。覆盖所有用户（Reach=5000），不做会被嫌弃。与#3共用图表组件，增量成本低 |
| **5** | **简化版二级目标拆解**（Challenge → 时段目标，2级） | ~1600（简化后Effort=1.5） | 用户明确要求"目标拆解"。MVP 做2级（不做3级），满足核心场景"8-9点≤1根" |

## 四、OST 框架（Objective-Strategy-Tactics）

### 4.1 OST 树

```
[O] 用户3个月不放弃习惯
 │
 ├── [S1] 让习惯进展在"当下"可见（从天级反馈→时段级反馈）
 │    ├── T1.1 打破"一天一次"限制，支持一天多次带时间戳打卡
 │    ├── T1.2 每次打卡后实时显示"今日累计 vs 目标"
 │    └── T1.3 时段内快速重复打卡（点"+"直接+1，降低操作成本）
 │
 ├── [S2] 让目标从"抽象"变"可行动"（从30天大目标→此刻的小指令）
 │    ├── T2.1 支持二级目标拆解：挑战 → 时段目标（8-9点≤1根）
 │    ├── T2.2 AI辅助拆解：用户说"我要戒烟"，AI建议拆解为时段目标
 │    └── T2.3 父目标进度自动由子目标聚合上卷
 │
 ├── [S3] 让失败从"终点"变"信号"（从binary成败→软硬目标混合）
 │    ├── T3.1 软目标：超出只提醒不扣分，不中断streak
 │    ├── T3.2 硬目标：超出扣分+中断streak（用户可设"底线"）
 │    └── T3.3 软目标超出时AI给替代行为建议（而非说教）
 │
 └── [S4] 让数据从"数字"变"洞察"（从完成率→行为模式识别）
      ├── T4.1 24小时时段分布图：发现"我何时最容易破戒"
      ├── T4.2 趋势折线+目标线叠加：发现"我在变好还是变差"
      └── T4.3 日历热力图：长期坚持的视觉成就感
```

### 4.2 三大升级如何协同支撑 O

```
    ┌─────────────────────────────────────────────┐
    │         O: 3个月不放弃习惯                   │
    │           （核心指标：D30留存 ≥ 40%）         │
    └──────────────────────┬──────────────────────┘
                           │
           ┌───────────────┼───────────────┐
           │               │               │
     ┌─────▼─────┐   ┌─────▼─────┐   ┌────▼──────┐
     │ 二级打卡   │   │ 目标拆解   │   │ 报表体系   │
     │ (解决"看   │   │ (解决"做  │   │ (解决"调  │
     │  不见")    │   │  不了")   │   │  不了")   │
     └─────┬─────┘   └─────┬─────┘   └────┬──────┘
           │               │               │
           │    互相支撑   │    互相支撑   │
           └───────┬───────┘───────┬───────┘
                   │               │
            ┌──────▼──────┐ ┌──────▼──────┐
            │ 软目标机制   │ │ AI洞察分析  │
            │ (解决"放弃  │ │ (解决"看不  │
            │  太痛")     │ │  懂数据")   │
            └─────────────┘ └─────────────┘
```

**协同逻辑**：
1. **二级打卡**让用户"看见"行为 → 但光看见不够，还需要知道"此刻该做什么"
2. **目标拆解**让用户"知道此刻该做什么" → 但光知道不够，偶尔做不到时会挫败
3. **软目标**让用户"做不到也不放弃" → 但光坚持不够，还需要知道"往哪个方向调"
4. **报表体系**让用户"看见模式、调整策略" → 形成闭环，进入正向螺旋

> 缺任何一环：光有打卡没拆解→不知道做什么；光有拆解没软目标→容易放弃；光有软目标没报表→盲目坚持。

## 五、产品方案设计

### 5.1 数据模型重构

> 原则：不考虑兼容老代码。分层结构 Model层 ← infra/domain层 ← Service层 ← API层。

#### 5.1.1 Challenge 模型（重构）

```python
# app/models/challenge.py
class Challenge(Base):
    __tablename__ = "challenges"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    user_id: Mapped[str] = mapped_column(String(128), index=True, nullable=False)
    title: Mapped[str] = mapped_column(String(256), nullable=False)
    description: Mapped[str] = mapped_column(Text, default="")
    category: Mapped[str] = mapped_column(String(32), default="build")

    # 目标配置（重构核心）
    task_type: Mapped[str] = mapped_column(String(16), default="binary")
    # task_type: binary | counter | timer | text
    # 移除 step 类型（二级打卡后step被时段目标替代）

    target_value: Mapped[float] = mapped_column(Float, default=1.0)
    # 每日目标值（如每天≤5根、每天喝8杯水）

    unit: Mapped[str] = mapped_column(String(16), default="次")
    # 目标单位（根/杯/分钟/页）

    direction: Mapped[str] = mapped_column(String(8), default="increase")
    # direction: increase(越多越好,如喝水) | decrease(越少越好,如抽烟)
    # 决定了"超出目标"的语义：increase超=超额完成, decrease超=破戒

    goal_type: Mapped[str] = mapped_column(String(8), default="hard")
    # goal_type: soft(督促,超出不惩罚) | hard(底线,超出扣分+断streak)

    # 拆解配置
    decompose_mode: Mapped[str] = mapped_column(String(16), default="none")
    # decompose_mode: none(不拆) | time_slot(按时段拆) | custom(自定义子目标)

    # 时段拆解参数（decompose_mode=time_slot 时生效）
    slot_hours: Mapped[int] = mapped_column(Integer, default=1)
    # 每个时段多少小时（默认1小时一个时段，如8-9点/9-10点）
    slot_target_value: Mapped[float] = mapped_column(Float, default=0.0)
    # 每个时段的目标值（如每小时≤1根），0表示继承日均分配

    # 挑战周期
    duration_days: Mapped[int] = mapped_column(Integer, default=30)
    start_date: Mapped[str] = mapped_column(String(10), default="")
    end_date: Mapped[str] = mapped_column(String(10), default="")
    status: Mapped[str] = mapped_column(String(16), default="active")

    # AI与展示
    ai_plan: Mapped[str] = mapped_column(Text, default="[]")
    color: Mapped[str] = mapped_column(String(16), default="#6366f1")
    icon: Mapped[str] = mapped_column(String(16), default="🎯")
    scene_template: Mapped[str] = mapped_column(String(32), default="")
```

### 5.4 软目标机制设计

#### 5.4.1 软硬目标对比

| 维度 | 软目标(Soft) | 硬目标(Hard) |
|------|-------------|-------------|
| 语义 | "希望值"——有方向，不强制 | "底线"——不可逾越 |
| 超出后果 | 提醒，不扣分，不断streak | 扣分，中断streak |
| 可视化 | 虚线 | 实线 |
| 颜色 | 琥珀色(amber) | 红色(red) |
| AI语气 | 鼓励+建议替代行为 | 警示+建议调整 |
| 适用场景 | 戒烟(每天≤5根，超了提醒) | 戒酒(每天≤0杯，喝了=失败) |
| 积分影响 | 达成+10分，超出不扣 | 达成+10分，超出-15分 |

#### 5.4.2 软目标督促的"不挫败"设计

**原则：让用户"看见差距"但不"感受惩罚"。**

| 触发条件 | 系统反应 | 语言示例 | 心理学依据 |
|---------|---------|---------|-----------|
| 达到软目标100% | 正向反馈 | "今天的软目标已达成，继续加油！" | 正强化 |
| 超出软目标1-20% | 温和提醒 | "已超出软目标1根。没关系，趋势比单次更重要。" | Nudge：默认非惩罚 |
| 超出软目标20-50% | 模式提示 | "今天超出较多。你在14-15点破戒最多，明天这个时段试试替代活动？" | 框架效应：从"失败"重框为"模式" |
| 超出软目标>50% | 建议调整 | "连续3天超出软目标。也许目标设得太严了？要不要调整？" | 目标设定理论：目标应可实现 |
| 超出硬目标 | 底线警示 | "今日已超出硬目标底线。streak中断，但明天可以重新开始。" | 明确后果但不羞辱 |

#### 5.4.3 软目标值设置策略

> 目标设定理论(Locke & Latham)：有效目标应"有挑战但可实现"。

**AI辅助设定软目标值的规则**：

```
如果用户是新习惯（无历史数据）：
    软目标 = 用户自述当前水平的 80%
    # 如用户说"现在每天抽10根"，软目标设为8根

如果用户有7天以上历史数据：
    软目标 = 最近7天平均值的 80%
    # 动态调整，确保可实现

如果用户连续3天超出软目标：
    AI建议上调软目标 = 最近7天平均值
    # "你最近7天平均6根，软目标设为8根太宽松了，建议调整为6根"

如果用户连续7天达成软目标：
    AI建议下调软目标 = 当前值 × 80%
    # "你连续7天达成目标，是时候提高挑战了！建议降至4根"
```

#### 5.4.4 与积分/streak/护盾的集成

| 机制 | 软目标超出 | 硬目标超出 |
|------|-----------|-----------|
| 积分 | 不扣分，但不获得额外奖励 | 扣除当日基础积分的50% |
| Streak | 不断 | 断裂（可用护盾/仁慈修复） |
| 护盾 | 不触发 | 可用护盾抵消1次 |
| 小队 | 不影响 | 影响小队完成率 |
| 心情 | 建议记录"有点难" | 建议记录"需要支持" |

## 六、关键决策点

### 6.1 决策一：二级打卡的"二级"定义

**问题**：是"一天多次"还是"目标层级"还是两者都有？

**深度分析（3轮思考）**：

**第1轮（表面理解）**：
- "一天多次" = 时间维度（同一目标一天记录多次）
- "目标层级" = 结构维度（大目标拆成小目标）
- 看似独立，可分开实现

**第2轮（场景验证）**：
- 用户场景："8点到9点抽了2根，目标是一根"
  - 需要"一天多次"：8点记1根、9点记1根
  - 需要"目标层级"：8-9点这个时段有独立目标≤1根
  - **两者缺一不可**：只有一天多次→知道记了2根但不知道对标什么目标；只有目标层级→知道目标是1根但无法记录实际2根

**第3轮（架构推演）**：
- 数据模型上：CheckIn 支持 `sub_goal_id` 外键 → 同时支持"属于Challenge"和"属于SubGoal"
- 交互上：用户点"+"打卡时，系统根据 timestamp 自动匹配到对应 SubGoal（时段目标）
- 结论：**两者是同一件事的两面**。"一天多次"是行为（用户做了什么），"目标层级"是对照（对标什么目标）

**决策**：**两者都有，且天然耦合**。MVP 实现模型支持 `Challenge → SubGoal → CheckIn` 三层结构，CheckIn 一天可多条。用户感知到的是"我每个时段有目标，我在每个时段记录实际值"。

### 6.2 决策二：25分钟停止拆解是硬规则还是AI建议

**问题**：用户说"25分钟打卡就一件事情，就不需要拆解到更细"——这是系统硬约束还是AI软建议？

**深度分析（3轮思考）**：

**第1轮（用户意图）**：
- 用户原话是描述性的（"就不需要"），不是要求强制（"必须禁止"）
- 用户想要的是"系统帮我判断什么时候不用再拆了"，而非"系统禁止我拆"

**第2轮（Nudge理论验证）**：
- Nudge 理论：默认选项的力量。硬规则 = 强默认，AI建议 = 弱默认
- 用户有限理性：拆解到很细时容易"分析瘫痪"，硬规则减少决策负担
- 但完全硬规则可能误伤：有些习惯确实需要15分钟级拆解（如番茄钟工作法）

**第3轮（成本与灵活性权衡）**：
- 硬规则：实现简单（一行校验），但不够灵活
- AI建议：实现复杂（需AI判断），但更个性化
- **折中方案**：MVP做硬规则（≤25分钟不可再拆），Phase 2 升级为AI建议+用户可覆盖

**决策**：**MVP 阶段为硬规则（系统约束），Phase 2 升级为 AI 建议（可覆盖）**。

**MVP 硬规则实现**：
```
当用户尝试创建 SubGoal 时，系统检查：
  如果 SubGoal 的预估完成时间 ≤ 25分钟：
    禁止创建，提示"该目标预计25分钟内可完成，无需再拆解"
```

**Phase 2 升级**：
```
AI 评估拆解必要性：
  - 如果预估 ≤ 25分钟：建议"无需拆解"（用户可坚持拆）
  - 如果预估 > 25分钟但 < 60分钟：提示"可拆可不拆"
  - 如果预估 > 60分钟：建议"建议拆解为2-3个子时段"
```

**理由**：
1. Atomic Habits 两分钟法则的延伸（2分钟→25分钟，番茄钟心智）
2. 硬规则减少用户决策负担（Nudge理论：默认约束的力量）
3. 25分钟对应番茄钟，用户心智模型已建立，无需额外学习

### 6.3 决策三：软目标失败扣分还是不扣分

**问题**：超出软目标时，扣分还是不扣分？如何不挫败？

**深度分析（3轮思考）**：

**第1轮（两种方案对比）**：
- 扣分：有"牙齿"，督促力强，但容易挫败→放弃
- 不扣分：无压力，但督促力弱→软目标形同虚设

**第2轮（心理学依据）**：
- Beeminder 金钱承诺：有效但大陆用户门槛高
- Habitica HP损失：游戏化有效但非玩家用户过重
- Nudge理论：默认选项的力量 > 惩罚的力量
- 目标设定理论：目标应"有挑战但可实现"，如果超出就惩罚→用户会设很低的目标来逃避惩罚

**第3轮（行为经济学视角）**：
- 损失厌恶(Loss Aversion)：人对损失的痛苦感是同等收益快乐感的2倍
- 如果软目标超出扣分→用户感受到的是"损失"→痛苦→回避→放弃
- 如果软目标超出不扣分但"不奖励"→用户感受到的是"没得到"→轻度遗憾→可接受
- **关键洞察**：软目标的价值不在于"惩罚超出"，而在于"让差距可见+提供调整建议"

**决策**：**软目标超出不扣分，采用"可见+提醒+建议"三步督促**。

| 步骤 | 机制 | 效果 |
|------|------|------|
| 可见 | 实时显示"今日累计 vs 软目标"，超出时琥珀色高亮 | 让差距看得见 |
| 提醒 | 超出时弹出AI温和提醒（非惩罚语气） | 触发反思 |
| 建议 | AI给出替代行为建议或模式洞察 | 引导调整 |

**积分处理**：
- 软目标达成：+基础积分（正激励）
- 软目标超出：0积分（不扣分，但也不奖励→轻度遗憾）
- 硬目标超出：-50%当日积分（底线惩罚，但有护盾可抵消）

**Streak处理**：
- 软目标超出：streak 不断（保护心理安全）
- 硬目标超出：streak 断裂（可修复，已有仁慈机制）

**为什么不挫败**：
1. **不扣分** → 不触发损失厌恶
2. **不断streak** → 不打破连续性心理
3. **AI语言正向** → "趋势比单次重要"而非"你又失败了"
4. **给建议而非说教** → "试试替代活动"而非"你不应该抽"
5. **动态调整目标** → 连续超出时建议上调目标，避免目标过严
